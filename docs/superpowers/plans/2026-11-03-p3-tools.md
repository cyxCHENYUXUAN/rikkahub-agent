# P3 工具、审批与工作区 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox syntax. User requested continued execution without phase-by-phase questions.

**Goal:** 实现架构中 P3 的真实工具、工作区、审批、输出和恢复，再依次推进 P4/P5。
**Architecture:** core 保留唯一会话写者与普通 Java 端口；两个插件实现工具和本地 I/O；backend 组合并持久审批投影。
**Tech Stack:** Java 17 / Boot 4.1.2 / Jackson 3 / Jupiter 6 / SQLite。
**Spec:** ../specs/2026-11-03-p3-tools-design.md；权威 backend-architecture.md。

## Global Constraints

- 不访问现有 data 用户库或私有凭据、不调用付费模型；只用隔离临时数据和本地协议 fixture。
- 不回改 V1–V6、不创建 Git 仓库或提交；所有副作用执行经过 Pipeline。
- 单写者、短事务、取消后真实 drain；失败不重跑 Shell。
- 每阶段验收后删除该阶段新增临时测试和临时产物，保留原4架构检查；删除后 clean verify。
- v1 为明确 PIPE terminal，resize unsupported；真实 PTY 和 OS 沙箱不虚报。

## Review Focus

- Windows junction/ADS、新文件真实父目录与外部同步修改：路径不逃逸，不把 cwd 称为沙箱。
- 后台/终端创建取消竞态与孙进程持有输出句柄：实际退出前不报告 drain。
- HTTP 已决定但 decided 未提交崩溃：恢复 unavailable，不执行工具。
- 并行组中审批和取消：只有 writer 提交事件，独占屏障不越过仍存活任务。
- 超大输出和磁盘故障：内存有界，持久引用可读，不能重跑副作用。
